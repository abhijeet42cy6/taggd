Universal SaaS Design System

Style Guide

A comprehensive, opinionated design system built for B2B SaaS products. Warm, document-native aesthetics. Reduced chrome, maximum clarity. Scales from simple forms to complex data-entry workflows.

Typeface DM Sans + DM Mono
Accent #e16f3d
Mode Light + Dark

Motion is purposeful and fast. Micro-interactions use 0.12–0.15s ease. Page-level entrances use a spring curve. Collapsible sections use the smooth easing curve for height transitions.

Two navigation components: breadcrumbs for hierarchical context and the close button for dismissing overlays/modals.

Breadcrumb

Mono, 12px, uppercase, 0.04em tracking. Separator is › at 40% opacity. Last item is not a link. Items are --text-muted at rest, --accent on hover.

Close Button
32×32px circle. Background: --border. On hover: --border-focus. Position: top-right of page header. Always a true button element.
16 — Patterns

Footer Actions Pattern

Every multi-step panel has a sticky footer with back/forward navigation. Space-between layout: left side = back or cancel (ghost), right side = primary or grouped secondaries. A keyboard hint lives in the left side on step 0.

Esc to cancel
Gate progression The primary Continue button is disabled (opacity: 0.45, cursor: not-allowed) until the required action on that step is complete. Never hide it — always show disabled state to telegraph what's expected.

19 — Rules

Core Design Rules

These rules govern how all components are composed together. They are not optional.

Color usage
✓ Do Use semantic colors (green/amber/red/blue) exclusively for status communication. Use accent for the single interactive highlight per surface.
✗ Don't Use semantic colors decoratively. Don't use red for branding, amber for accent, or blue for a primary button.
Hierarchy
✓ Do One primary button per logical group. Use the ghost/secondary variants to support it.
✗ Don't Place two primary buttons adjacent to each other. If you think you need two, reconsider the flow.
Typography
✓ Do Use DM Mono for all machine data (IDs, computed values, timestamps, financial figures, breadcrumbs, uppercase labels).
✗ Don't Use DM Mono for body copy, button labels, section titles, or instructions. These are human-authored text.
Borders & surfaces
✓ Do Use --border (low opacity) for containers at rest. Upgrade to --border-focus on hover or focus-within.
✗ Don't Add decorative borders or use high-opacity borders in a default/resting state. The system should feel light.
Accessibility
✓ Do Always pair color status with text or a dot indicator. Ensure focus rings are visible (3px accent-soft halo). Use disabled attribute on buttons that cannot be clicked.
✗ Don't Rely on color alone to communicate state. Don't suppress focus outlines — replace them with the design system's ring instead.
Max content width
Page width Forms and data-entry panels are capped at 680px. This keeps line lengths readable and prevents the form from spreading uncomfortably on wide screens. Dashboards and lists may use wider containers.
